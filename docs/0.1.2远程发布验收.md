## 源码与本地验证

Android `prepare` / `play` / `release` 共用 Main Handler：Main 调用立即执行，后台及 Kuikly Renderer 入队。MediaPlayer 在 Main 创建，系统事件、五秒超时、替换与释放在同一线程串行处理；播放器 identity 拒绝旧回调。后台 release 以 `RELEASED` 状态确认已执行，Main 提前关闭后已排队入口不得复活实例。iOS 继续要求主线程入口，OHOS Kotlin 继续要求所属 Kuikly 页面线程；本轮没有扩大这些合同。

本轮 Android 定向编译和 unit test 通过：`AndroidSoundPlayerTest` 2 项、共享 `SoundPlayerTest` 4 项，共 6 项，failure/error/skipped 均为 0。覆盖后台入口、Main 同步入口、SDK 创建线程、超时迟回调、Main 提前释放与排队请求资格；Robolectric 不代表真机播放。sound 的 iOS 行为 XML 是 2026-09-30 历史结果，本轮不计为重新执行的测试；本轮完整 staging 产物编译也不能替代设备音效验收。

发布规则的 metadata 7 项、严格 Maven checker 13 项、归档编排 3 项共 23 项通过，shell 语法与 diff 检查通过。归档编排验证历史版本字节不变、只归档所选版本、缺许可证或 publication 时不替换已有归档。正式发布使用隔离 staging 并完成完整归档门禁；安装脚本先前对未验收 `0.1.2` 的下载前拒绝已完成测试，发布后已填入真实 SHA。

## 独立消费与设备

首次独立 Android 消费未通过：解析先从 Eazy 仓库取得 Kuikly metadata，随后该镜像对应 AAR 的 HEAD 请求返回 404；不能将此结果归因于新组件 publication 缺失。腾讯 `maven-tencent` 的同坐标 GET 返回 200，实际文件哈希吻合。Eazy 稍后的 GET/HEAD 也返回 200，因此该记录只说明当时镜像 metadata 与 artifact 可用性不一致，不表示永久缺包。安装示例用 `exclusiveContent` 将 `com.tencent.kuikly-open` 固定到腾讯 `maven-tencent`，其他 SDK/插件仓库及组件版本保持；协调者正在按该固定源复验，尚不记录消费通过。

独立远程消费：通过。隔离组件文件与 descriptor 缓存后仅从 JitPack 下载精确版本；Android APK、D8、重复类及版本检查通过；iOS arm64/x64 编译、Simulator static Framework 导出与实际链接、版本检查通过；OHOS 五个组件 core/kuikly 编译及版本检查通过，live 不包含 OHOS 实现。Kuikly 使用腾讯 Maven 的专用 group 路由。没有本地源码、composite、mavenLocal 或 staging 替代远程制品。
