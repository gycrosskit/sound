## 本地行为检查

以下命令从仓库根目录执行。配置`ANDROID_HOME`与可运行Gradle的JDK；Kotlin/Native测试需要macOS、Xcode及iOS Simulator运行环境。Node测试转译真实ArkTS源码并使用受控SDK替身，`SOUND_TYPESCRIPT`可指定已有TypeScript模块。

```sh
bash gradlew :sound-core:testDebugUnitTest :sound-core:iosSimulatorArm64Test --max-workers=1
node verification/ohos-behavior.cjs
```

只运行受影响目标；需要确认本轮真实执行时加`--rerun-tasks`，不要把`UP-TO-DATE`算成新执行。平台测试结果XML位于`sound-core/build/test-results/`。这些测试不调用真实分享、认证、拨号或定位业务。

## 原生产物与独立消费

HarmonyOS工具链需要DevEco SDK、ohpm与hvigorw。在`ohos/`目录执行：

```sh
ohpm install --all
hvigorw --mode module -p module=SoundNative@default -p product=default assembleHar --no-daemon
```

安装与公开API消费工程按[接入指南](接入指南.md)和[README](../README.md)执行；`scripts/verify.sh`是更广的维护检查，不是每次小改动的必跑全套。构建/本地HAR消费不等于OHPM Registry或本版远程消费。Maven、Swift/Pod与HAR按各自版本验证。

## Native Module 验证

本版源码 Maven / Git Pod `0.1.6`；发布及远程消费状态以对应 Release 证据为准。仅在独占 Worktree 操作；真实 SDK 为 Kuikly Maven `2.28.0-2.0.21-ohos` / iOS Pod `OpenKuiklyIOSRender 2.28.0`。

```bash
ANDROID_HOME=/Users/guoyang/Library/Android/sdk ./gradlew \
  --init-script scripts/ci-repositories.gradle \
  :sound-kuikly:testDebugUnitTest \
  :sound-kuikly:compileDebugKotlinAndroid \
  :sound-kuikly:compileKotlinIosArm64 \
  :sound-kuikly:compileKotlinIosSimulatorArm64 \
  :sound-kuikly:compileKotlinOhosArm64 --max-workers=1 --no-parallel
bash scripts/ci-build-kuikly-render.sh "$PWD/build/kuikly-native-pod" GYCSound/Kuikly
```

handler 行为回归与真实 SDK receiver 测试在 [`sound-kuikly/src/androidUnitTest`](../sound-kuikly/src/androidUnitTest)。handler 使用受控原生动作/播放器；receiver 继承真实 SDK，验证注册工厂、独占 owner、Main 排队后销毁与迟回调资格，不打开真实系统页面或播放网络音频。

本轮 iOS Pod source install + xcodebuild 已在 Simulator arm64 完整编译链接通过，含真实 SDK 与组件 receiver；Swift 单独 typecheck 也通过。Android/iOS/OHOS Kotlin 最终编译与测试结果以本轮报告为准，不复用旧测试数量冒充新增测试执行。

源码 CI 沿用原 Android/native job：Android 执行新 receiver/handler 测试；native 编译新增 Kotlin iOS target、旧 OHOS target，并用上述单次 Pod build 编译 SDK 与 receiver。正式 ReleaseNative 对新版本读取精确远程 Maven、以同一 Git tag 构建远程 Pod，然后以真实生成的 consumer framework 编译 [`KuiklyAssembly.swift`](../verification/KuiklyAssembly.swift)。旧版本 consumer 与 publication 清单保留原合同。

精确远程 Maven/Git Pod 消费以对应 Release 证据为准；宿主 Shared 导出/注册与真机行为需单独验收。iOS Pod 不携带 KMP framework，宿主必须把 handler 从既有 Shared framework 导出；装配探针不是第二个生产 runtime。

原 source Native 门禁在同一次 Pod 构建后执行 `scripts/test-ios-module.sh Products目录`，使用真实 SDK/组件 framework，在独占临时 Simulator 验证重复 `invalidate`、SDK `dealloc`、销毁前已排队调用和 off-Main 释放。测试结束删除自身创建的 Simulator，不操作宿主已有设备。
