# Sound 接入指南

本轮 Maven `0.1.3` 为候选版本，修复 iOS Main 线程入口，远程发布尚待验收；以下示例对应候选版本。历史 Maven `0.1.2` prerelease 已发布并通过 JitPack 全制品审计；HAR 独立保持 `@gycrosskit/sound@0.1.0`。归档 SHA、渠道边界及独立消费状态见 [0.1.2 远程发布验收](0.1.2远程发布验收.md)。

## 状态与准备语义

`SoundPlayer` 暴露 `state: StateFlow<SoundState>`、`prepare(remoteUrl: String?)`、`play()` 和 `release()`。状态只描述远端准备及实例生命周期，不表示当前正在播放，也不证明本地资源可用。

空地址清除远端并回到 `LOCAL_ONLY`；非 HTTPS、无 Host、含空白或用户凭据的地址被拒绝，进入 `REMOTE_FAILED`。相同 URL 正在准备或已就绪时去重；失败后再次 `prepare` 可以重试。更换 URL 取消旧准备并屏蔽迟到回调。准备完成不会自动播放，需宿主显式调用 `play()`。

播放器只提供单音效重播，不提供混音、队列、持久磁盘缓存或业务事件去重。宿主提供短小且系统可解码的音频，例如 PCM WAV，并验证设备与编码组合。

## Android

```kotlin
import io.github.gycrosskit.sound.AndroidSoundPlayer

val sound = AndroidSoundPlayer(context, R.raw.host_sound)
sound.prepare("https://cdn.example.com/sound.wav")
sound.play()
// 页面或拥有音效的会话退出：
sound.release()
```

宿主提供有效的 `res/raw` 资源 ID。AAR Manifest 声明 `android.permission.INTERNET`，只保留 Application Context。远端使用 MediaPlayer 与 `USAGE_ASSISTANCE_SONIFICATION`，本地使用 MediaPlayer.create 默认音频属性；本地资源不可用时停止该次播放，不抛给业务。Android `prepare` / `play` / `release` 可从后台或 Kuikly Renderer 调用：Main 上立即执行，其他线程入队。SDK 创建、回调、超时、替换与释放由 Main 串行处理；后台 `release` 返回不代表已完成，以 `state.phase == RELEASED` 确认。

## iOS

```kotlin
import io.github.gycrosskit.sound.IosSoundPlayer

val sound = IosSoundPlayer("host_sound", "wav")
// 第三个参数可传宿主自己的 NSBundle，默认 mainBundle。
sound.prepare("https://cdn.example.com/sound.wav")
sound.play()
sound.release()
```

宿主将文件加入对应 Bundle。Swift 直接调用时，将 `sound-core` 作为 `api` 依赖，并在宿主的 iOS `binaries.framework` 中 `export("com.github.gycrosskit.sound:sound-core:0.1.3")`；状态流观察可留在 Kotlin 层转给 Swift。不需要额外 Swift Package 或宿主 Swift 播放桥。组件不修改 AVAudioSession，全局音频会话、静音键、后台播放和与其他音频的交互由宿主决定。prepare/play/release 可从后台或 Kuikly Context 调用：Main 上立即执行，其他线程排入 Main，与预载、播放器和 generation 共用 Main。后台 release 返回只表示已入队，以 state.phase == RELEASED 确认播放器已停止、网络客户端已关闭且预载任务已取消；不等待已取消请求的底层网络清理。本地文件缺失或不能播放时静默结束该次播放。

## HarmonyOS 原生与 Kuikly

```shell
ohpm install @gycrosskit/sound@0.1.0
```

```typescript
import { SoundPlayer } from '@gycrosskit/sound';
const sound = new SoundPlayer(context.resourceManager, 'host_sound.wav', state => {
  // state.phase / state.remoteUrl
});
sound.prepare('https://cdn.example.com/sound.wav');
sound.play();
await sound.release();
```

宿主在自己的 `resources/rawfile` 放音频，并声明 `ohos.permission.INTERNET`。本地 rawfile 描述符按播放器串行释放后关闭；快速重播或销毁会取消本地准备。原生 `release()` 返回本地资源释放 Promise，远端 AVPlayer 异步释放已发起；状态立即变为 `RELEASED`。AVPlayer 使用 `STREAM_USAGE_GAME`。

Kuikly 两侧在各自页面中注册同名模块：

```kotlin
import io.github.gycrosskit.sound.kuikly.SoundModule

private val sound = SoundModule("host_sound.wav")
override fun createExternalModules() = mapOf(SoundModule.NAME to sound)
// 在 Kuikly 页面线程调用同一个 sound.prepare / play；页面退出调用 sound.release()。
```

```typescript
import { SoundModule } from '@gycrosskit/sound';
// 在 Renderer 的 getCustomRenderModuleCreatorRegisterMap() 返回的 Map 中注册。
modules.set(SoundModule.MODULE_NAME, () => new SoundModule());
```

Kuikly ArkTS 侧注册 HAR 导出的 `SoundModule.MODULE_NAME`（`GycSound`），Kotlin 侧注册 `io.github.gycrosskit.sound.kuikly.SoundModule("host_sound.wav")`，并把同一实例作为 `SoundPlayer` 使用。桥传递 URL、rawfile 名称和准备结果；业务事件由宿主触发。Kotlin 入口在 Kuikly 页面线程串行执行。宿主退出时显式调用 Kotlin `release()`，清除常驻回调；ArkTS `onDestroy()` 也关闭播放器。Kuikly 2.28.0 的原生 Module 只有 onDestroy，没有页面隐藏回调；隐藏时若业务需要停止，应由宿主在所属页面线程调用 release，恢复时创建新实例。

## 生命周期、超时和大小边界

`release()` 永久关闭实例且可重复调用；关闭执行后 `prepare` / `play` 均无效。Android/iOS 后台调用需要等 Main 发布 `RELEASED`，调用返回本身不等于关闭完成。重新进入页面或会话应创建新实例。关闭时停止播放、取消计时器和下载任务，替换或关闭后旧回调不会修改新状态。

| 平台 | 准备和大小边界 |
| --- | --- |
| Android | MediaPlayer 原生网络预缓冲；5 秒未 prepared 即失败。没有完整下载保证或库内字节上限；播放仍可能依赖网络。 |
| iOS | Darwin 完整下载到内存再解码，连接/请求/读超时均为 5 秒。最大 2 MiB；流式最多读取 2 MiB + 1 字节判断超限，不信任缺失或偏小的 Content-Length。空体、HTTP 非成功、超限或解码失败均回退。 |
| OHOS | AVPlayer 原生网络预缓冲；5 秒未 prepared 即失败。本地资源准备也有 5 秒取消超时。没有完整下载保证或库内字节上限；播放仍可能依赖网络。 |

HTTPS 准入针对宿主传入 URL；重定向与 TLS 由各平台网络栈处理。宿主应使用最终 HTTPS CDN 地址，确保重定向链同样使用 HTTPS。5 秒是准备/下载期限，不是整个播放过程的网络断连期限。Android/OHOS 需由宿主 CDN 限制音频大小与时长；组件不提供三端离线播放保证。

## 0.1.3 Android/iOS 线程合同

Android/iOS prepare/play/release 可由后台或 Kuikly Renderer/Context 调用，由组件排入 Main；Main 调用立即执行。播放器、预载结果、超时和生命周期操作在 Main 串行；Android 按播放器身份、iOS 按 generation 拒绝旧结果。后台 release 返回不代表关闭已执行，应观察 RELEASED；释放执行后排队入口不能复活实例。iOS 的入口调度不依赖会被 release 取消的预载 scope。Kuikly Kotlin 仍要求所属页面线程；RELEASED 只确认桥关闭，原生释放异步执行。
