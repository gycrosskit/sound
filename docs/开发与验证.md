# Sound 开发与验证

消费者用法见 [README](../README.md) 和[接入指南](接入指南.md)，历史检查结果见 [VERIFICATION.md](../VERIFICATION.md)。以下命令在仓库根目录执行。

配置 Android SDK 后执行 `bash scripts/verify.sh`。脚本使用 `--max-workers=1`，覆盖相关平台编译、行为检查、Maven metadata 及独立消费；真实音频播放仍需设备验收。

安装 DevEco SDK，把 `tools/node/bin`、`tools/ohpm/bin`、`tools/hvigor/bin` 加入 `PATH` 后，在 `ohos` 中执行：

```sh
ohpm install --all
hvigorw --mode module -p module=SoundNative@default -p product=default assembleHar --no-daemon
```

产物为 `sound-native/build/default/outputs/default/SoundNative.har`。`bash scripts/verify-har.sh` 使用已构建的本地 HAR 验证独立消费；file 依赖不等于 OHPM Registry 安装验收。ArkTS 行为检查使用真实源码与可控系统播放器替身，支持 `SOUND_TYPESCRIPT` 指定转译器。

Maven 全变体输出到 `build/maven`，独立消费者默认使用 JitPack；本地消费显式传 `-PsoundMavenRepo=<staging Maven 目录>`。发布在 macOS 构建，按不可变版本标签上传 Maven 归档并写入真实 SHA-256。JitPack 安装脚本校验归档，metadata 修复仅移除已知不适用于 JitPack 的 source/metadata 发布变体，保留平台 API/runtime。

已有记录覆盖远程 Maven 消费编译、iOS Simulator Framework 链接、Swift API typecheck、OHPM 精确版本 Registry 安装与独立 HAR 编译。行为替身、编译和 typecheck 不能代替真机播放、API 22 设备兼容或宿主音频会话验收。
